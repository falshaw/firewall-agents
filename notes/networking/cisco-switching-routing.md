# Cisco Switching & Routing Refresher

## Layer 2 Switching Fundamentals

### VLANs & Trunking

```
! VLAN creation
vlan 100
  name CDE_Payment
vlan 200
  name SWIFT_Zone
vlan 300
  name Corp_Users

! Trunk configuration (Nexus / IOS-XE)
interface Ethernet1/1
  switchport mode trunk
  switchport trunk allowed vlan 100,200,300
  switchport trunk native vlan 999
  no shutdown
```

**Key concepts:**

- **802.1Q** — standard VLAN tagging (4-byte header, 12-bit VLAN ID = 4094 VLANs)
- **Native VLAN** — untagged traffic. ALWAYS change from default VLAN 1 (security)
- **Voice VLAN** — separate VLAN for IP phones via CDP/LLDP
- **VLAN pruning** — only allow needed VLANs on trunks (reduce broadcast domain)

### Spanning Tree Protocol (STP)

```
! Rapid-PVST+ (default on Nexus, recommended)
spanning-tree mode rapid-pvst
spanning-tree vlan 100 priority 4096    ! Make this switch root for VLAN 100

! MST (Multiple Spanning Tree) — maps VLANs to instances
spanning-tree mode mst
spanning-tree mst configuration
  name CORP_MST
  revision 1
  instance 1 vlan 100-199      ! Payment VLANs
  instance 2 vlan 200-299      ! SWIFT VLANs
  instance 3 vlan 300-399      ! Corporate VLANs

! Root guard — prevent rogue switches becoming root
interface Ethernet1/10
  spanning-tree guard root

! BPDU guard — shutdown port if BPDU received (access ports)
interface Ethernet1/20
  spanning-tree bpduguard enable
  spanning-tree portfast
```

**STP variants comparison:**
| Feature | STP (802.1D) | RSTP (802.1w) | PVST+ | Rapid-PVST+ | MST |
|---------|-------------|---------------|-------|-------------|-----|
| Convergence | 30-50s | 1-3s | 30-50s | 1-3s | 1-3s |
| Per-VLAN | No | No | Yes | Yes | Per-instance |
| Use case | Legacy | Basic | Cisco | **Recommended** | Large-scale |

### EtherChannel / Port-Channel

```
! LACP (preferred over static/PAgP)
interface Ethernet1/1-2
  channel-group 10 mode active    ! LACP active

interface port-channel 10
  switchport mode trunk
  switchport trunk allowed vlan 100,200,300

! vPC (Virtual Port-Channel) — Nexus only
! Allows port-channel across two physical switches
vpc domain 1
  peer-keepalive destination 10.1.1.2 source 10.1.1.1
  role priority 100

interface port-channel 10
  vpc 10
```

**vPC key facts (Nexus):**

- Two Nexus switches act as one logical switch to downstream devices
- **Peer-keepalive link** — heartbeat (mgmt VRF, separate from peer-link)
- **Peer-link** — syncs MAC/ARP tables (2x 10G minimum, port-channel)
- **Orphan ports** — single-attached devices, need `vpc orphan-ports suspend`
- **CFS (Cisco Fabric Services)** — syncs config between vPC peers
- **Type 1 consistency check** — mismatched configs = vPC suspension (STP mode, VLAN, MTU)

### Port Security & L2 Hardening

```
! Port security — limit MACs per port
interface Ethernet1/30
  switchport port-security
  switchport port-security maximum 2
  switchport port-security violation shutdown
  switchport port-security mac-address sticky

! DHCP snooping — prevent rogue DHCP
ip dhcp snooping
ip dhcp snooping vlan 100,200,300
interface Ethernet1/1    ! Uplink to real DHCP server
  ip dhcp snooping trust

! Dynamic ARP Inspection (DAI)
ip arp inspection vlan 100,200,300
interface Ethernet1/1
  ip arp inspection trust

! IP Source Guard
interface Ethernet1/30
  ip verify source

! Storm control
interface Ethernet1/30
  storm-control broadcast level 10.00
  storm-control multicast level 10.00
  storm-control action shutdown
```

## Layer 3 Routing

### OSPF

```
! Single-area OSPF (small network)
router ospf 1
  router-id 10.0.0.1
  network 10.0.0.0 0.0.255.255 area 0

! Multi-area OSPF (large network)
router ospf 1
  router-id 10.0.0.1
  ! Area 0 = backbone (core switches)
  network 10.0.0.0 0.0.0.255 area 0
  ! Area 1 = CDE/Payment zone
  network 10.1.0.0 0.0.255.255 area 1
  ! Area 2 = Corporate
  network 10.2.0.0 0.0.255.255 area 2

  ! Stub area — no external routes (simplify payment zone)
  area 1 stub

  ! NSSA — stub but allows redistribution
  area 3 nssa
```

**OSPF LSA types:**
| LSA Type | Name | Generated by | Scope |
|----------|------|-------------|-------|
| 1 | Router | Every router | Intra-area |
| 2 | Network | DR | Intra-area |
| 3 | Summary | ABR | Inter-area |
| 4 | ASBR Summary | ABR | Inter-area |
| 5 | External | ASBR | Domain-wide |
| 7 | NSSA External | ASBR in NSSA | NSSA only |

**OSPF in a segmented network:**

- Core = Area 0 (backbone)
- Each security zone = separate area (CDE, SWIFT, Corp, DMZ)
- Stub areas for zones that only need default route (ATM network)
- Route summarization at ABRs to reduce routing table
- Authentication: `ip ospf authentication message-digest` on ALL links

### BGP

```
! eBGP to ISP
router bgp 65001
  neighbor 203.0.113.1 remote-as 65000
  neighbor 203.0.113.1 password 7 ENCRYPTED
  address-family ipv4 unicast
    neighbor 203.0.113.1 activate
    neighbor 203.0.113.1 route-map ISP-IN in
    neighbor 203.0.113.1 route-map ISP-OUT out
    neighbor 203.0.113.1 prefix-list ACCEPT-DEFAULT in
    network 198.51.100.0 mask 255.255.255.0

! iBGP with route reflectors (large network)
router bgp 65001
  neighbor 10.0.0.2 remote-as 65001
  neighbor 10.0.0.2 update-source Loopback0
  address-family ipv4 unicast
    neighbor 10.0.0.2 route-reflector-client

! BGP communities for policy
route-map TAG-CDE permit 10
  set community 65001:100    ! Tag CDE routes

! BGP path selection (13 steps, key ones):
! 1. Highest weight (Cisco-specific, local)
! 2. Highest local preference (iBGP)
! 3. Locally originated
! 4. Shortest AS-path
! 5. Lowest origin (i > e > ?)
! 6. Lowest MED
! 7. eBGP over iBGP
```

**BGP design notes:**

- eBGP to ISPs (dual-homed for redundancy)
- iBGP internally with route reflectors (avoid full mesh)
- Communities tag routes by security zone
- Prefix lists: only accept default route from ISP, advertise only your own public space
- **BFD (Bidirectional Forwarding Detection)** — sub-second failover

### VRF-Lite (Virtual Routing and Forwarding)

```
! VRF for network segmentation (without ACI)
vrf definition CDE
  rd 65001:100
  address-family ipv4

vrf definition SWIFT
  rd 65001:200
  address-family ipv4

vrf definition CORP
  rd 65001:300
  address-family ipv4

! Assign interfaces to VRFs
interface Vlan100
  vrf forwarding CDE
  ip address 10.1.0.1 255.255.0.0

interface Vlan200
  vrf forwarding SWIFT
  ip address 10.2.0.1 255.255.0.0

! Route leaking between VRFs (controlled via firewall)
! Static route pointing to firewall for inter-VRF traffic
vrf definition CDE
  address-family ipv4
    route-target export 65001:100
    route-target import 65001:999    ! Import from shared services

! Verify
show vrf
show ip route vrf CDE
```

**VRF vs ACI comparison:**
| Feature | VRF-Lite | ACI VRF |
|---------|---------|---------|
| Config | CLI per device | APIC policy push |
| Scale | ~200 VRFs per switch | 3000+ per fabric |
| Policy | ACLs/firewall | Contracts/Filters |
| Visibility | Per-device show commands | Centralized APIC GUI |
| Change mgmt | Per-device config | Single policy change |

### HSRP/VRRP (First-Hop Redundancy)

```
! HSRP (Cisco proprietary, most common in Cisco campus and DC networks)
interface Vlan100
  ip address 10.1.0.2 255.255.0.0
  standby 1 ip 10.1.0.1          ! Virtual IP
  standby 1 priority 110          ! Higher = active
  standby 1 preempt               ! Take over when available
  standby 1 authentication md5 key-string SECRET
  standby 1 timers 1 3            ! Hello 1s, hold 3s

! VRRP (open standard, used with multi-vendor)
interface Vlan100
  vrrp 1 ip 10.1.0.1
  vrrp 1 priority 110
  vrrp 1 preempt
```

## Nexus 9000 Specifics (ACI Hardware)

### NX-OS vs IOS Key Differences

| Feature       | IOS/IOS-XE                 | NX-OS                                                      |
| ------------- | -------------------------- | ---------------------------------------------------------- |
| Mode entry    | `interface fa0/1`          | `interface Ethernet1/1`                                    |
| Save config   | `write memory`             | `copy run start`                                           |
| VTP           | Yes                        | No (use manual VLAN)                                       |
| Port-channel  | PAgP/LACP                  | LACP/vPC                                                   |
| Default route | `ip route 0.0.0.0 0.0.0.0` | Same                                                       |
| Features      | Always on                  | `feature ospf`, `feature bgp`, `feature vpc` (must enable) |
| Rollback      | Limited                    | `checkpoint` / `rollback`                                  |

```
! NX-OS feature enablement
feature ospf
feature bgp
feature vpc
feature lacp
feature dhcp
feature interface-vlan

! Checkpoint and rollback (NX-OS safety net)
checkpoint BEFORE_CHANGE
! ... make changes ...
! If something breaks:
rollback running-config checkpoint BEFORE_CHANGE
```

### VXLAN/EVPN (and How ACI Differs)

```
! ACI uses VXLAN under the hood for fabric forwarding
! You don't configure this manually in ACI mode
! But understanding helps:

! VXLAN = MAC-in-UDP encapsulation
! VNI (VXLAN Network Identifier) = 24-bit (16M segments vs 4094 VLANs)
! VTEP (VXLAN Tunnel Endpoint) = each leaf switch
! EVPN = control plane for VXLAN (replaces flood-and-learn)

! In ACI:
! - Spine = IS-IS underlay + COOP (Council of Oracles Protocol)
! - Leaf = VTEP endpoints
! - APIC = policy controller
! - Endpoint info inside the fabric = COOP (leaf -> spine), not EVPN
! - MP-BGP carries external (L3Out) routes; MP-BGP EVPN only between pods/sites
! - You configure EPGs/contracts, ACI programs iVXLAN forwarding and zoning rules
```
