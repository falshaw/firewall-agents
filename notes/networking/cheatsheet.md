## OSPF

### Key Concepts

| Term   | Description                                                       |
| ------ | ----------------------------------------------------------------- |
| Area 0 | Backbone - all other areas must connect to it                     |
| ABR    | Area Border Router - connects areas                               |
| ASBR   | Autonomous System Boundary Router - redistributes external routes |
| LSA    | Link-State Advertisement                                          |
| DR/BDR | Designated Router / Backup (on broadcast segments)                |
| Cost   | Metric = Reference BW / Interface BW                              |

### Area Types

| Type           | External LSAs | Summary LSAs | Default Route  |
| -------------- | ------------- | ------------ | -------------- |
| Normal         | Yes           | Yes          | No             |
| Stub           | No            | Yes          | Yes (from ABR) |
| Totally Stubby | No            | No           | Yes (from ABR) |
| NSSA           | Type 7 only   | Yes          | Optional       |

### LSA Types

| Type | Name          | Generated By | Scope         |
| ---- | ------------- | ------------ | ------------- |
| 1    | Router LSA    | Every router | Within area   |
| 2    | Network LSA   | DR           | Within area   |
| 3    | Summary LSA   | ABR          | Between areas |
| 4    | ASBR Summary  | ABR          | Between areas |
| 5    | External LSA  | ASBR         | Entire AS     |
| 7    | NSSA External | ASBR in NSSA | NSSA area     |

### Neighbor States

```
Down → Init → 2-Way → ExStart → Exchange → Loading → Full
```

### Troubleshooting Checklist

1. Neighbor not forming? Check: Area ID, subnet mask, hello/dead timers, authentication, MTU
2. Routes missing? Check: Area types (stub blocking externals?), summarization, filter-lists
3. Suboptimal path? Check: Cost, reference bandwidth, interface bandwidth settings

## BGP

### Key Concepts

| Term            | Description                                                   |
| --------------- | ------------------------------------------------------------- |
| AS              | Autonomous System (16-bit: 0-65535, 32-bit: up to 4B)         |
| eBGP            | Between different AS numbers                                  |
| iBGP            | Within same AS number                                         |
| Next-Hop        | Where to send traffic (eBGP changes, iBGP doesn't by default) |
| AS-Path         | List of AS numbers the route has traversed                    |
| Route Reflector | Reduces iBGP full-mesh requirement                            |

### BGP Path Selection (in order)

1. **Highest Weight** (Cisco-specific, local)
2. **Highest Local Preference** (iBGP, default 100)
3. **Locally originated** (network, redistribute, aggregate)
4. **Shortest AS-Path**
5. **Lowest Origin** (IGP < EGP < Incomplete)
6. **Lowest MED** (Multi-Exit Discriminator)
7. **eBGP over iBGP**
8. **Lowest IGP metric** to next-hop
9. **Oldest route**
10. **Lowest Router ID**
11. **Lowest neighbor IP**

**Mnemonic:** "**W**e **L**ove **O**ranges **A**s **O**ranges **M**ean **E**ating **I**s **O**K **R**ight **N**ow"

### BGP Communities

| Community    | Value       | Meaning                          |
| ------------ | ----------- | -------------------------------- |
| NO_EXPORT    | 65535:65281 | Don't advertise to eBGP peers    |
| NO_ADVERTISE | 65535:65282 | Don't advertise to any peer      |
| LOCAL_AS     | 65535:65283 | Don't advertise outside local AS |

### BGP Message Types

| Message      | Purpose                                         |
| ------------ | ----------------------------------------------- |
| OPEN         | Establish peering (AS, Router ID, capabilities) |
| UPDATE       | Advertise/withdraw routes                       |
| KEEPALIVE    | Peer alive (default every 60s)                  |
| NOTIFICATION | Error, connection teardown                      |

### BGP States

```
Idle → Connect → Active → OpenSent → OpenConfirm → Established
```

### Troubleshooting

- Stuck in **Active**: TCP connection failing (ACL, reachability, MD5 mismatch)
- Stuck in **OpenSent**: OPEN message rejected (AS mismatch, Router ID conflict)
- **Routes not received**: Filters, max-prefix, route not in neighbor's table
- **Routes not installed**: Next-hop unreachable, better route exists, admin distance

## VRF (Virtual Routing and Forwarding)

### Concept

- Separate routing tables on same physical device
- L3 equivalent of VLANs
- Each VRF has its own RIB (Routing Information Base)
- Route Distinguisher (RD) makes routes unique in MPLS/BGP
- Route Target (RT) controls import/export between VRFs

### Use Cases

- Multi-tenancy on shared infrastructure
- Separating management from production traffic
- PCI-DSS CDE isolation
- Guest vs. corporate network separation

### Configuration Pattern (Cisco-style)

```
ip vrf MGMT
  rd 65001:100
  route-target export 65001:100
  route-target import 65001:100

interface GigabitEthernet0/0
  ip vrf forwarding MGMT
  ip address 10.100.0.1 255.255.255.0

ip route vrf MGMT 0.0.0.0 0.0.0.0 10.100.0.254
```

### JunOS Equivalent (Routing Instances)

```
set routing-instances MGMT instance-type virtual-router
set routing-instances MGMT interface ge-0/0/0.0
set routing-instances MGMT routing-options static route 0.0.0.0/0 next-hop 10.100.0.254
```

## PBR (Policy-Based Routing)

### Concept

- Route based on policy (source IP, application) instead of destination
- Override normal routing table decisions
- Use Cases: Force specific traffic through specific paths, WAN load distribution

### Pattern (Cisco)

```
ip access-list extended MATCH-WEB
  permit tcp any any eq 80
  permit tcp any any eq 443

route-map PBR-WEB permit 10
  match ip address MATCH-WEB
  set ip next-hop 10.0.0.2

interface GigabitEthernet0/0
  ip policy route-map PBR-WEB
```

## IPSec VPN

### IKE Phase 1 (ISAKMP SA)

```
Purpose: Authenticate peers, establish secure channel
Parameters: Encryption, Hash, DH Group, Authentication, Lifetime

Common Settings:
- AES-256-CBC encryption
- SHA-256 hash
- DH Group 14 (2048-bit) minimum
- Pre-shared key or Certificate
- Lifetime: 28800 seconds (8 hours)
```

### IKE Phase 2 (IPSec SA)

```
Purpose: Negotiate data encryption parameters
Parameters: Encryption, Hash, PFS Group, Lifetime, Proxy ID

Common Settings:
- AES-256-CBC encryption
- SHA-256 HMAC
- PFS Group 14
- Lifetime: 3600 seconds (1 hour)
- ESP (Encapsulating Security Payload)
```

### ESP vs AH

| Feature          | ESP            | AH  |
| ---------------- | -------------- | --- |
| Encryption       | Yes            | No  |
| Authentication   | Yes            | Yes |
| Integrity        | Yes            | Yes |
| Protocol #       | 50             | 51  |
| NAT-T compatible | Yes (UDP 4500) | No  |

### VPN Troubleshooting

1. Phase 1 failing? Check: Peer reachability, PSK, proposals, NAT-T
2. Phase 2 failing? Check: Proxy-ID/encryption domains, PFS, proposals
3. Tunnel up but no traffic? Check: Routing, interesting traffic, security policies
4. Intermittent drops? Check: DPD, rekey timers, MTU/fragmentation

## Layer 2 Essentials

### VLAN

```
VLAN Types:
- Access port: Single VLAN, untagged
- Trunk port: Multiple VLANs, 802.1Q tagged
- Native VLAN: Untagged on trunk (change from VLAN 1!)
```

### STP (Spanning Tree Protocol)

| Variant | Standard | Convergence                  |
| ------- | -------- | ---------------------------- |
| STP     | 802.1D   | 30-50 sec                    |
| RSTP    | 802.1w   | 1-2 sec                      |
| MSTP    | 802.1s   | 1-2 sec (multiple instances) |

### Port Security Best Practices

- Disable unused ports
- BPDU Guard on access ports
- Root Guard on downstream trunk ports
- DHCP Snooping
- Dynamic ARP Inspection
- 802.1X for authentication

## Troubleshooting Methodology

### The 7-Layer Check

```
1. Physical: Link light? Cable? SFP?
2. Data Link: MAC table? VLAN correct? STP?
3. Network: IP address? Subnet? Default gateway?
4. Transport: Port open? Firewall? NAT?
5. Session: Connection established? Timeout?
6. Presentation: SSL/TLS? Certificate?
7. Application: DNS? App config? Logs?
```
